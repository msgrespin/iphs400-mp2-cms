# AWM at Kenyon — CMS

The goal of this project was to create a small CMS for the Association of Women in Mathematics club at Kenyon. The site allows officers to post events and pages without having to get into the deep details of coding a website. Currently, for the scope of this project, the admin and editor sites run solely on my laptop. The public site is more accessible on my GitHub Pages (linked below).

## Live URL

[https://msgrespin.github.io/iphs400-mp2-cms/](https://msgrespin.github.io/iphs400-mp2-cms/)

This is the published site only. The admin console runs on your own machine and is
never put on the internet.

## Run locally

You need Python 3.12 or newer and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/msgrespin/iphs400-mp2-cms.git
cd iphs400-mp2-cms
uv sync
cp .env.example .env
uv run python scripts/seed_demo.py   # demo Accounts, Posts and Pages
uv run cms serve                     # then open http://localhost:8000/admin
```

`/admin` sends you to the sign-in page. Sign in with one of the demo Accounts:


| Role                  | Email                 | Password                        |
| --------------------- | --------------------- | ------------------------------- |
| Admin (Co-VP)         | `admin@example.test`  | `CMS_ADMIN_PASSWORD` in `.env`  |
| Editor (Social Chair) | `editor@example.test` | `CMS_EDITOR_PASSWORD` in `.env` |


With the `.env.example` values the passwords are `change-me-admin` and
`change-me-editor`. Change them in `.env` before you seed if you want others.
`http://localhost:8000/` shows the public site as Visitors see it.

To write the published content out as static HTML, run `uv run cms publish` (it
writes `site/`, which is generated, never edit it by hand). `uv run cms deploy`
pushes `site/` to the `gh-pages` branch.

The app loads `.env` itself (`cms serve`, `publish`, `deploy`, and
`scripts/seed_demo.py`). A real environment variable overrides the same name in
`.env`.

## What is here

```text
app/               the FastAPI app: Accounts, content, Markdown sanitizing, publishing, routes/
templates/         Jinja templates: admin/ (the console) and public/ (the published site)
site/              generated by `cms publish`; never edit by hand
scripts/           seed_demo.py, check_submission.py, usage_report.py
tests/             pytest suite, with helpers such as client_as("editor")
docs/              adr/ decision records, screenshots/, handoff/, transcripts/, the manual and rubric
notes/             field notes, token budget plan, usage ledger
.claude/hooks/     context-usage hooks and the transcript saver
CONTEXT.md         the project glossary
```

Run the tests with `uv run pytest`, and check a submission with
`uv run python scripts/check_submission.py --stage 2`.
